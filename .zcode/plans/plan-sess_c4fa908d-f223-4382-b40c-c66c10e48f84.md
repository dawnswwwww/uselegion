# 防重叠架构改造：抄 jcode/grok-build 的单一缓冲区模型

## 目标
根除 inline 模式的重叠问题。参考 jcode 和 grok-build 两个项目验证过的防重叠秘诀：**所有内容画进单一 ratatui 缓冲区 + 固定高度预算布局**，彻底删除向原生 scrollback 单独 emit 文本的双写入者链路。

## 根因回顾（已论证）
重叠不是 ratatui Layout 的数学问题（各段 y 严格连续不相交），而是 **inline 模式的双写入者**：
- ratatui `Viewport::Inline` diff 渲染底部 N 行
- 同时 `emit_finalized_messages` 往原生 scrollback 写纯文本
两写入者共享终端，边界处（resize/光标移动/高度跳变）产生重叠/残影。
Fullscreen 模式当前走 alternate screen 单缓冲区、无 scrollback emit、**不重叠**（用户只报 inline 有问题），证明单缓冲区模型是正解。

## 核心决策
1. **inline 模式也进 alternate screen**（像 jcode 的 `ratatui::init()`），不再用 `Viewport::Inline`。两种模式渲染模型统一为单缓冲区。
2. **删除 scrollback emit 链路**：`emit_finalized_messages`、`message_to_scrollback`、`tool_card_to_scrollback`、`last_emitted_scrollback_index`、`scrollback_tx` 直写通道。
3. **保留两个模式名**（向后兼容 `/mode` 命令、已存配置、`ScreenMode` 枚举）。区别收窄为：两者都走单缓冲区；鼠标捕获在两种模式都启用（inline 原本禁用是因 scrollback 要原生滚动，现在不需要）。
4. **`draw_ui` 的固定高度预算布局不变**（已在上一轮实现：transcript `Min(5)` + 其余 `Length` 固定）——这正是参考项目的承重墙，单缓冲区下数学上不可能重叠。

## 变更清单

### 1. `tui.rs`（核心：统一终端初始化）
- `run_terminal`（tui.rs:411-482）：把 inline 分支的 `Viewport::Inline` + `reset_emitted_index` 删掉，让 inline 也走 `EnterAlternateScreen` + `EnableMouseCapture` + `Terminal::new(backend)`（和 fullscreen 合并为一条路径）。teardown 对应合并。
- `tui_loop`（tui.rs:486）：删除 `scrollback_tx` 参数。
- 删除 tui.rs:538-546 的 `emit_finalized_messages` 调用块。
- 删除 `use inline::{INLINE_HEIGHT, reset_emitted_index}`（tui.rs:31）。

### 2. `inline.rs`（删除整个模块）
- `emit_finalized_messages`、`reset_emitted_index`、`message_to_scrollback`、`tool_card_to_scrollback`、`INLINE_HEIGHT` 及其 6 个测试全部删除。
- 从 `mod` 声明中移除（crates/legion-cli/src/tui/mod.rs 或 lib.rs 的 `mod inline`）。

### 3. `state.rs`（删字段）
- 删除 `last_emitted_scrollback_index: usize`（state.rs:234）。

### 4. `writer.rs`（简化签名）
- `WriterThread::spawn` 不再单独返回 scrollback `Sender`，改为只返回 `(TermWriter, WriterThread)`（TermWriter 内部已持有 tx）。更新调用点和测试。

### 5. 回滚上一轮的 `INLINE_HEIGHT=10` 改动
- 已随 inline.rs 删除一并消失，无需单独处理。

## 不改动的部分
- `draw_ui` 布局逻辑（5 段，固定高度预算）——已是参考项目模式，单缓冲区下直接生效。
- 队列面板的渲染与键盘交互（events.rs/widgets.rs/render.rs 的 queue 部分）——独立于渲染模型。
- `ScreenMode` 枚举、`/mode` 命令、配置持久化——保留向后兼容。

## 测试计划
- 删除 inline.rs 的 6 个 scrollback 测试（随模块删除）。
- 新增 `run_terminal` 层的测试若有则适配（多为集成/pty 测试，预期不受影响，因行为对外可见的是"终端接管"）。
- 现有 282 个 lib 单测预期全绿（渲染/事件逻辑未变）。
- pty 测试（tui_pty.rs、setup_pty.rs）验证终端交互仍正常。

## 验证门槛
`cargo build -p legion-cli && cargo clippy -p legion-cli --all-targets && cargo test -p legion-cli && cargo fmt -- --check`，再加全 workspace 门禁。

## 风险与取舍
- **失去原生 scrollback**：历史只能用应用内 PgUp/PgDn 滚动，不能用终端滚轮看 scrollback。这是参考项目都接受的取舍，也是本次改造的前提。
- `Viewport::Inline` 删除后，legion 退出时 alternate screen 丢弃，终端历史里不留会话记录（与 vim/less 行为一致）。
- 改动集中在渲染模型层，不影响业务逻辑（消息队列、流式、工具调用）。
