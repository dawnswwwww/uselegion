## 目标

把 CLI 默认运行模式从 `Local`(写死嵌入式、不探测 gateway)改为 `Auto`(探测 gateway → 接入;探测不到 → 回退嵌入式)。

这样:
- **不启动 gateway 也能正常用**——`Auto` 探测失败即回退 `Local`,行为与今天一致,零网络依赖。
- **gateway 一旦在跑,TUI 自动接入**——为后续远程管控场景(发现 + 远程 chat 续接)铺好路。

`Auto` 的探测(300ms 超时)和回退逻辑都已存在(`tui.rs:216-239`、`main.rs:759-787`),本次只改"默认值",不新增代码路径。

## 改动点(共 3 个文件)

### 1. `crates/legion-cli/src/driver.rs` — 核心逻辑 + 文档 + 测试

**(a) `resolve_cli_mode` 函数体(`:65-72`)**

把 `_local`(被忽略)变成有意义的逃生舱:`--local` 强制 `Local`(永不探测、永不联网);无 flag 时默认 `Auto`。

```rust
pub fn resolve_cli_mode(local: bool, gateway: bool) -> CliMode {
    if gateway {
        CliMode::Gateway
    } else if local {
        CliMode::Local
    } else {
        CliMode::Auto
    }
}
```

**(b) 同函数 doc 注释(`:55-64`)** 改写:默认从 `Local` 改为 `Auto`(探测 gateway、回退嵌入式);说明 `--local` 现在是"强制本地、跳过探测"的显式开关;保留 `--gateway` 的语义说明。

**(c) 两个单元测试(`:728-743`)**

- `resolve_cli_mode_defaults_to_local` → 重命名为 `resolve_cli_mode_defaults_to_auto`,断言 `(false, false) == Auto`。
- `resolve_cli_mode_gateway_flag_wins_and_local_is_default` → 重命名为 `resolve_cli_mode_local_and_gateway_flags`,断言:
  - `(true, false) == Local`(`--local` 现在强制本地)
  - `(false, true) == Gateway`
  - `(true, true) == Gateway`(冲突时 gateway 优先,注释同步更新)

同步更新两个测试里的内联注释。

## 不在本次范围(需要你知道的代价,留待后续决定)

1. **每次启动多 ~300ms 探测**(无 gateway 时)。这是 Auto 的固有成本。若后续想消除,可考虑把探测失败结果短期缓存,但本次不做。
2. **每次回退都打印 `EMBEDDED_NOTICE` 到 stderr**。Auto 成为默认后,无 gateway 的用户每次启动都会看到这行。本次不改文案(它是诚实的状态告知);若你觉得太吵,后续可降级为只在首次或 verbose 时打印。
3. **远程管控的"发现"缺口**(`sessions.list` RPC + client 注册表)本次不补。默认改 Auto 只是让 TUI "能接入 gateway",真正"能远程枚举/发现"仍需后续方案 B。
